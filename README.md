# Said's Digital Universe

PERSONAL PORTFOLIO — SAID

ROLE

Act as a world-class creative director, award-winning digital designer, senior frontend engineer, interaction designer, and creative technologist.

You are not creating a conventional developer portfolio.

You are creating a highly original digital experience that functions as Said's personal portfolio.

The website itself must demonstrate three things:

Exceptional development ability.

Strong creative thinking.

An unusual and highly refined approach to digital design.

The portfolio should feel so carefully designed and engineered that the visitor immediately understands that this person cares deeply about how things are built.

CORE CONCEPT

The portfolio should communicate:

"I cannot be reduced to a category."

Said is not presented simply as a developer, designer, AI specialist, or automation builder.

He is presented as a person who builds things across technology, AI, systems, design, and creative development.

The website should therefore feel like a personal digital universe rather than a standard portfolio template.

The visitor should feel that they are EXPLORING something rather than simply scrolling through a website.

Do not over-explain.

Let the interface, projects, interactions, typography, and visual language communicate the identity.

IMPORTANT

DO NOT create a generic developer portfolio.

Avoid:

Standard hero sections

Generic portfolio grids

Generic SaaS aesthetics

Generic AI imagery

Excessive purple/blue gradients

Robot imagery

Stock photography

Generic glassmorphism

Excessive 3D decoration

Unnecessary animations

Template-looking cards

"About me / Skills / Experience / Contact" layouts copied from typical portfolios

Every visual decision must feel intentional.

VISUAL DIRECTION

Overall aesthetic:

Minimal
Experimental
Editorial
Technical
Futuristic
Human
Premium
Precise

Think:

Apple-level restraint
Linear-level product design
Vercel-level typography
Framer-level interaction
Awwwards-level art direction

But DO NOT copy any of them.

Create an original visual identity.

COLOR SYSTEM

Primary background:

Near-black.

Use several extremely subtle dark surfaces to create depth.

Typography:

White / off-white / muted gray.

Borders:

Very subtle 1px borders.

Accent:

Choose ONE sophisticated accent color.

Use it sparingly.

The accent should appear primarily for:

active states

important interactions

project metadata

subtle highlights

interactive elements

Do not turn the entire website into a neon interface.

TYPOGRAPHY

Use a premium modern sans-serif.

Prefer:

Inter
Satoshi
General Sans
or another high-quality contemporary grotesk.

Use very large typography strategically.

Typography should be one of the main visual elements of the website.

Large headlines should feel editorial rather than like standard website headings.

Create strong contrast between:

enormous headlines

tiny metadata

compact labels

body text

EXPERIENCE

The website should feel like a digital environment.

Scrolling should not feel like moving through blocks stacked vertically.

Use:

carefully choreographed reveals

subtle parallax

scale transitions

opacity transitions

horizontal movement where appropriate

masked text reveals

image transitions

cursor interactions

hover transformations

smooth navigation transitions

Animations must feel deliberate and expensive.

Never animate something simply because it is possible.

Motion should communicate hierarchy, interaction, or progression.

LANDING EXPERIENCE

The first screen should be extremely minimal.

Display:

SAID

along with a concise statement describing the type of person he is.

Do NOT use a generic headline such as:

"Hi, I'm Said, a developer."

Instead create a visually powerful statement that feels like a manifesto.

Possible direction:

"I build things that shouldn't exist yet."

This text can be refined later.

The hero should contain subtle visual movement.

The background may include:

extremely subtle grid

dynamic light

noise texture

tiny interface details

responsive visual elements

These elements should react subtly to cursor movement.

The first impression must be memorable without becoming visually chaotic.

PERSONAL IDENTITY

Create a visual identity around:

SAID

Do not make the logo overly complicated.

The name itself should be the identity.

Use typography, spacing, motion, and composition to make the word "SAID" recognizable.

NAVIGATION

Do not use a conventional large navigation bar.

Create a minimal navigation system.

Possible structure:

SAID / 2026

MENU +

When MENU is activated, reveal a fullscreen navigation interface.

Navigation items:

01 — WORK
02 — ABOUT
03 — JOURNAL
04 — CONTACT

The menu transition should feel like entering another layer of the website.

WORK / PROJECTS

This is the most important section.

Projects are not ordinary cards.

Treat every project as a digital artifact.

Each project should have:

large visual preview

project number

title

category

technologies

short description

year

interactive hover state

Example structure:

01

PROJECT NAME

AI / AUTOMATION / DEVELOPMENT

[large visual]

EXPLORE →

On hover:

preview transforms

typography shifts subtly

image changes scale

cursor responds

metadata becomes more visible

The interaction should make the project feel alive.

PROJECT DETAIL PAGES

Each project must feel like an experience.

Do not simply create:

Title
Description
Screenshot
Technologies

Instead structure project pages as visual stories.

Possible structure:

01 — THE PROBLEM

02 — THE IDEA

03 — THE SYSTEM

04 — THE BUILD

05 — THE RESULT

Use large visual compositions.

Show:

interfaces

architecture

workflows

diagrams

screenshots

code fragments when useful

system visualizations

metrics when available

The visitor should understand not only WHAT was built, but HOW Said thinks.

THE LAB

Create a section called:

THE LAB

This is not an "experiments" section.

It is a living archive of things Said creates.

It can contain:

small tools

AI experiments

automation systems

interfaces

prototypes

concepts

visual experiments

things currently being built

Each item should feel like an artifact.

Display statuses such as:

BUILDING
LIVE
ARCHIVED
EXPLORING

This section should allow the portfolio to evolve over time.

ABOUT

Do not create a conventional biography.

Create a visual manifesto.

Use large statements and small fragments of information.

The section should communicate:

curiosity

creativity

technical ability

constant learning

interest in AI

systems thinking

design

building real things

Use typography and spacing as the primary visual tools.

Avoid a giant paragraph explaining everything.

SKILLS

Do not create a standard grid of:

Python
JavaScript
React
n8n
etc.

Instead represent capabilities through a visual system.

For example:

BUILD
DESIGN
AUTOMATE
THINK
LEARN
EXPLORE

Each capability can reveal the technologies and areas underneath.

This should feel like exploring a system rather than reading a résumé.

CONTACT

The contact section should feel like the conclusion of the experience.

Headline:

LET'S BUILD SOMETHING.

or another similarly strong statement.

Instead of immediately showing a boring form, create a simple interaction:

"What are you building?"

Then reveal the contact form progressively.

Include:

Name
Email
Message

and a refined submit interaction.

Also include direct contact/social links where appropriate.

CURSOR

Create a custom cursor system for desktop.

The cursor should:

subtly react to interactive elements

expand over buttons

change state over projects

create subtle magnetic interactions

communicate clickable areas

Do not make it annoying.

On mobile, disable custom cursor behavior completely.

MICROINTERACTIONS

Pay extreme attention to microinteractions.

Include polished:

hover states

focus states

active states

button transitions

navigation transitions

image transitions

text reveals

loading states

scroll indicators

menu transitions

The goal is to create the feeling of a carefully handcrafted interface.

RESPONSIVE DESIGN

Desktop is important, but the website must also be exceptional on:

tablet

mobile

small mobile screens

Do not simply shrink the desktop layout.

Create intentional mobile compositions.

Custom cursor interactions must disappear on touch devices.

Typography must scale intelligently.

Animations must remain smooth.

PERFORMANCE

Despite the visual complexity, maintain excellent performance.

Use:

lazy loading

optimized images

efficient animations

transform/opacity-based motion where possible

minimal unnecessary JavaScript

reusable components

clean architecture

Avoid expensive effects that damage performance.

TECHNICAL QUALITY

Build the project using a clean, maintainable architecture.

Components should be reusable.

Create a consistent design system for:

spacing

typography

borders

radii

buttons

cards

animations

colors

Do not create every section as an isolated visual hack.

The code should be as carefully structured as the design.

CONTENT

Do not invent fake professional achievements, fake clients, fake companies, fake revenue, or fake testimonials.

Use realistic placeholder content where information is not yet available.

Make it extremely easy to replace project data later.

Create project data in a structured format rather than hardcoding every project individually.

FINAL DESIGN STANDARD

Before considering the site complete, ask:

Does this look like a template?

If yes, redesign it.

Does this look like an ordinary developer portfolio?

If yes, redesign it.

Does every section feel intentionally designed?

Does the interaction feel premium?

Does the typography carry visual weight?

Does the site communicate Said's personality without excessive text?

Does the portfolio itself demonstrate exceptional frontend development?

Does exploring a project feel different from simply clicking a card?

Does the website have moments that make the visitor stop and think:

"How did he build this?"

If not, continue refining.

The final result should feel like a highly personal digital experience created by an obsessive designer/developer who spent an enormous amount of time refining every detail.

Do not optimize for "more features."

Optimize for:

IDENTITY
CRAFT
ORIGINALITY
INTERACTION
DETAIL
